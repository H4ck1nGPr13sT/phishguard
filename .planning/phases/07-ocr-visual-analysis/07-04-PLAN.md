| upload bytes → Pillow/EasyOCR/OpenCV decode | Raw bytes decoded into pixels + neural inference |

## STRIDE Threat Register (ASVS V5 Input Validation, V12 File Handling)

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-08 | Denial of Service | oversized upload | mitigate | 8MB byte cap enforced BEFORE decode; reject → HTTP 400 |
| T-07-09 | Denial of Service | decompression bomb (tiny file, huge pixels) | mitigate | Pillow default Image.MAX_IMAGE_PIXELS (not disabled) in the 07-01 loader; size cap as first line |
| T-07-10 | Tampering | polyglot / disguised non-image file | mitigate | Extension allowlist (.png/.jpg/.jpeg) + Image.verify() structural validation; decode only via Pillow |
| T-07-11 | Tampering / Info Disclosure | uploaded bytes persisted or EXIF executed | mitigate | Process entirely in-memory via io.BytesIO; never write to disk; pixel data only (no EXIF parsing) |
| T-07-12 | Denial of Service | startup hang on EasyOCR model download (offline env) | mitigate | Warm-up wrapped in try/except → NullOCRBackend fallback; startup never crashes (Pitfall 3) |
| T-07-SC | Tampering | pip installs | mitigate | Cleared in RESEARCH.md Package Legitimacy Audit; no new packages beyond Plan 07-01 |

**Blocking note:** T-07-08 through T-07-11 are high-severity input-validation controls for the new upload boundary and MUST all be implemented and covered by Task 3 tests before this plan is considered done.
